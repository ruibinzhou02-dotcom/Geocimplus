# GeoCIM+ V3 开发清单（待测试后确认）

日期：2026-09-21。状态：规划草案，尚未启动 V3 功能开发。

本轮决定：先让 V2 在主域名稳定可用，由用户实际测试，再选择 V3 范围。下面是结合现有代码整理的建议，不代表全部功能已承诺在同一版本完成。

## 1. 当前线上基础

- 正式入口：https://geocimplus.com/ 。兼容入口 `/v2.html`；旧版保留 `/v1.html`。
- 首页：城市更新、城市交通、数字孪生。只有城市更新中的沙头示例已经可运行，后两者仍是占位。
- 输入：Shapefile 配套文件 / ZIP、GeoJSON、GeoTIFF、EPW；数据目录识别点、线、面、栅格及坐标。ArcInfo Grid / ADF 能识别格式，但浏览器不能直接解码，需先转为带空间参考的 GeoTIFF。
- 场景：连续地形网格、建筑下方地面估算、建筑模型、LST、地形贴图、独立平面底图、沿地形抬高的路网薄层。
- 图层：分析、只读展示、结果三类；符号系统、属性表、分类色带、透明度、边框及展示数据的分析副本。
- Circuit：类型约束、数字滑条、矢量和栅格输入、面积/长度、统计、代表点、缓冲、核密度、栅格转渔网、地面平整、曲面、安全公式、输出节点，支持中英文。
- 输出：GeoJSON、统计 JSON、PNG、含分层 3dm 与贴图的 Rhino ZIP、`.geocim` 项目包。
- 固定示例在服务器计算；新建项目和自有数据在浏览器本地计算。模型 API 尚未接入。

## 3. 沙盒先做什么

建议第一阶段采用“受限公式 / 已注册函数电池”：输入指定的栅格渔网或属性列，输出新渔网、字段或统计结果。节点面板包括输入声明、公式、输出类型、样例预览、错误和运行日志。它是 Circuit 的一个电池组，不新增独立的万能脚本页面。

例如：`LST 渔网 + 阈值滑条 → 超阈值判断 → 结果图层 → 符号系统`；或者 `建筑工作副本 → 高度筛选 → 缓冲 → 边界裁剪 → 结果图层`。这些可以直接复用现有数据验证，不需要先购买 API 或扩大服务器。

较完整的 Python 电池单独列为第二阶段。浏览器 Worker 主要提供线程分离，不等于完整权限沙盒；选定运行环境后还要验证网络隔离、文件访问、死循环中止、内存限制与依赖清单。普通用户的新任务始终优先本地执行；公开服务器只继续提供固定示例的受控计算。

## 5. 先测试 V2 的操作表

1. 访问主域名，确认出现城市更新 / 城市交通 / 数字孪生三张卡片，切换中文与英文。
2. 进入城市更新，观察地形、建筑、LST、路网和平面底图；旋转/缩放，反馈破面、悬空、闪烁位置。
3. 打开 CIRCUIT，改一个数字滑条，运行；观察结果是否符合预期。记录最不顺手的添加电池、连线或分组操作。
4. 新建本地项目，导入一套 SHP 配套文件和一个 GeoTIFF；确认类型、CRS、图层类别、工作副本、属性表和色带。
5. 输出一个结果图层，保存 `.geocim` 后重新打开；导出 PNG、GeoJSON 和 Rhino 包并在相应软件检查。

反馈格式：页面/步骤、实际结果、期望结果、截图；涉及数据时附文件名、格式和 CRS。先修复 V2 阻断问题，再挑选 V3 第一包（建议 A1–A7 中最影响使用的部分）。

## 6. 开发与上线顺序

1. 保持 V2 线上稳定，保留本次发布的回滚指针。
2. 用户测试后确认 V3 范围与验收场景，再建立独立 V3 分支/预览入口；本轮不改写 V2 成 V3。
3. 先实现一条可完整复现的本地流程，包括输入、坐标、沙盒、结果、保存和导出。
4. 再扩展分组、批量或渲染。静态前端构建在本机完成，用户数据仍在本地。
5. 通过类型/单位/NoData/取消/安全边界测试及浏览器实际操作后，提供 V3 预览；确认后才将主入口切换，保留 V2 访问和回滚。

本轮仅完成 V2 主域名发布与本清单，不把上表的计划项标记为已实现。
