# GeoCIM V2.3：显示维护与资源库对照

日期：2026-09-21。本轮延续 V2，V1 网页与 GitHub 源码均保留。版本比较入口见 [ChatGPT 阅读指南](V1与V2对比及ChatGPT阅读指南.md)。

## 本次变化

1. **符号系统选图层**：在面板顶部增加 `Layer / 图层` 下拉框，按分析/展示/结果分组，与左侧图层树使用同一选中状态。既可在左侧选择，也可直接在符号系统中切换。
2. **地形实体底座**：有效地形顶面保持不变，外围边和 NoData 孔洞边生成竖直侧壁，底面封到参考平面。使用单一外壳，避免每个渔网单元生成重复内墙。场景中可开关“地形实体底座”；Rhino 的 `03_TerrainMesh` 相应输出闭合网格。
3. **彩色合成**：原来的 `111` 是 ArcInfo 栅格堆栈，三个子通道为 `111c1/c2/c3`，此前只显示第一个通道。现在从三个原始通道生成 1024×969 的 8-bit RGB+Alpha 展示 GeoTIFF，使用共同有效掩膜保留透明区。原始文件哈希检查不变。
4. **影像专用显示项**：卫星图层用“彩色合成 / 第一通道灰度”替代无实际作用的矢量单色设置；不透明度仍独立控制。地形贴图和平面底图是两个图层，各自设置。Rhino 导出的贴图跟随这两个图层的彩色/灰度模式。
5. **科学顺序色带**：新增 Viridis、Magma、Plasma、Inferno，保留 thermal/terrain/purple。四套新色带使用原作者 256 个采样色值（转换为 8-bit RGB），集中在 `scientific-palettes.mjs`；符号系统、场景和 Circuit 共享 `RAMPS` 注册表。符号系统有色带预览条。

## 地形与影像必须区分的含义

- 底座参考高程优先与平面底图一致；没有平面底图时采用低于全部有效顶点的显示基准。它只是三维展示封闭体，不是实测地下边界、不修改 DEM，也不改变分析数值；导出元数据记录此用途。
- 有效顶面之外的 NoData 不会被编造高程补满。斜边的阶梯轮廓来自网格与掩膜分辨率；增加侧壁不会提高原数据分辨率。
- 当前彩色顺序为 **R=111c1、G=111c2、B=111c3**。原始栈文件能确定通道顺序，`prj.adf` 和元数据能确定 WGS84 地理坐标，但没有红/绿/蓝光谱身份标记。因此界面、GeoTIFF 和报告均保留“通道含义待核实”，不宣称已验证真彩色。
- 这不是给一张灰度图伪上色：三个不同通道均来自用户原始栅格。若后续拿到原始 RGB 波段说明或源 GeoTIFF，应更新映射及核实状态。
- 纯白的有效像元与透明 NoData 是不同情况，不能为美观将所有白色像元自动抹除；如原数据把背景写为有效白色，需要明确背景规则后再处理。
- 已保存的旧 `.geocim` 包包含旧数据快照，不会被静默替换；要看本次彩色底图请从首页重新打开城市更新示例。

## 科研配色依据

“顶刊配色”不是固定的一组色值。根据数据类型和读图目标选择：数值大小用顺序色带，相对零值/基准的偏差用发散色带，无序类别用离散颜色；同时检查色觉缺陷可读性和灰度打印。色带不能掩盖缺测、偏差或单位问题。

- Crameri, Shephard & Heron (2020), *The misuse of colour in science communication*, Nature Communications 11, 5444：[论文](https://www.nature.com/articles/s41467-020-19160-7)。参考其感知均匀与避免误导性彩虹色带的原则，本次没有复制论文图片。
- [BIDS/Matplotlib 官方色带说明](https://bids.github.io/colormap/)及[原始色值](https://github.com/BIDS/colormap/blob/master/colormaps.py)：Viridis/Magma/Plasma/Inferno 按 CC0 发布；本次直接提取数值数据，不执行下载的 Python 文件。来源文件 SHA-256 记录在生成的模块头部。
- [ColorBrewer](https://colorbrewer2.org/)：后续发散、顺序和分类配色的选择参考，可按色盲/打印条件筛选。本次尚未导入其配色数组，避免把参考方案写成已实现。
