## 2. V1、V2 实际对比

| 方面 | V1 | V2 主线 |
| --- | --- | --- |
| 网站入口 | `/v1.html`，保留对照 | `/` 与 `/v2.html`，正式主入口 |
| 产品结构 | 地图展示＋右侧分析工作台；沙头预设和个人数据 | 场景首页；城市更新可运行，城市交通/数字孪生占位；新建本地项目 |
| 三维显示 | MapLibre 地图上的建筑拉伸、路网、边界、人口专题 | Three.js 独立三维场景、DEM 渔网连续面、建筑、路网薄层、LST、地形贴图和平面底图 |
| 示例建筑数据 | 原建筑约 5306 条，`height` | 新建筑 3369 条，`BLDG_HEIGH`；不同数据集，数量变化不能直接当作“丢失建筑” |
| 人口数据 | 已有原人口网格专题显示 | 当前新示例未自动加入旧人口网格；仍可作为用户矢量图层导入，迁移是否默认加入需讨论 |
| 栅格 | 公开浏览器版以灰度预览和采样统计为主 | 数值 GeoTIFF、米制渔网、均值/双线性/最近邻、LST 和 RGB 显示影像；ArcInfo ADF 仍需先转换 |
| 图层 | 按数据图层控制，工作空间区分预设/个人数据 | 分析、展示、结果母图层；展示几何属性只读，可复制成分析副本；图层树和符号系统双入口选层 |
| 样式 | 建筑高度专题、透明度、选中透明度、统计卡 | 单色、分级、唯一值、网格边框、图例、色带和影像显示；V1 个别控制并未逐项移植 |
| 属性表 | 字段选择、按属性筛选/选择与选中高亮 | 支持属性选择、结果表及工作数据副本修改；分析数据与固定展示数据分开 |
| 分析入口 | 基础工具＋本地对话＋早期 Circuit | 分析页以对话预设为主；分析工具放 Circuit；场景保留栅格转渔网 |
| Circuit | 初版可拖动/缩放/分组流程 | 类型端口、数值输入/滑条、栅格/地形/EPW/安全公式、结果节点；仍不是完整 GH Data Tree |
| 气象 | 无独立气象流程 | EPW 插件及逐时基础展示；没有完成 UTCI/PET 或 CityComfortPlus 接入 |
| 计算位置 | 当前公开浏览器版的个人数据在浏览器计算；旧本机 FastAPI 上传流程是另一运行方式 | 固定示例白名单计算在服务器；新建项目、自有文件及编辑后的数据在浏览器/Worker 运行 |
| 保存与导出 | 公开版个人数据主要在页面内存，导出 GeoJSON/PNG/参数；刷新可能丢失未导出数据 | `.geocim` 项目包和浏览器项目记录，GeoJSON/JSON/PNG、含分层 3dm 和贴图的 Rhino ZIP |
| AI / 代码执行 | 有账户/API 预留及本地后端接入代码，不代表公开站已连接模型 | 公开站尚未接模型 API；安全公式采用受限语法，无任意 Shell/Python/SQL 执行 |
| 资源风格 | Lucide SVG 图标较多，浅灰/紫色 | 浅灰/紫色延续，但存在 Unicode 图标；应统一语义、尺寸、线宽和资源入口 |

共同保留的目标：新建任务本地运行，原始文件不覆盖；需要发布的固定示例才放服务器；图层、颜色、分析和输出彼此关联；中英文切换；后续按场景扩展。

## 3. 建议逐项对比，不急着删除 V1

先评估 V1 的五项体验：人口图层、顶部统计卡、对话预设表达、选中要素透明度、地图交互与图标一致性。确认哪些对 V2 仍有价值，再迁移；不把两套 UI 的所有按钮直接堆在一起。

| 步骤 | 做什么 | 通过条件 |
| --- | --- | --- |
| A：并行对比（现在） | 保留两个公开入口和 GitHub 源码；用户按相同操作测试 | 列出必须保留、合并、放弃的功能，不只比较截图 |
| B：迁移 | 在 V2 补齐批准的功能，统一图标/样式/色带资源 | 同一测试数据的筛选、结果、单位和导出可对照 |
| C：冻结 V1 | 在 GitHub 建立明确的 V1 归档标记及说明，不改写历史 | 可以按归档版本重建；原始 GIS 数据和密钥继续不入库 |
| D：网页退役（待用户确认） | 关闭 `/v1.html` 或显示迁移到 V2 的页面，检查共用静态资源与接口依赖 | V2 无断链；旧版站点备份可恢复；仓库源码/分支/历史不删除 |

现有部署会继承上一发布目录的静态文件，因此未来只从新包中删去 `v1.html` 并不能保证退役。应在专门的退役发布中处理入口路由与公开文件，并明确保留共用资源，不能删除整个 `src/` 或 `/assets/`。
