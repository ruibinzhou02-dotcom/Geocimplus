## 1. V2 固定原则

1. 用户新建项目、导入、分析和自然语言实验默认在本地执行。当前服务器只托管静态页面和审核后的示例数据。
2. 栅格进入分析流程后，统一转为可控分辨率的规则网格（渔网）。每个网格记录源像元数量、有效像元数量、平均值、最小值、最大值和 NoData 比例。
3. 分析图层、地形图层和底图图层分开管理。底图不参与数值分析；分析结果不得反向改写底图。
4. 网格边界是独立样式，可设置颜色、宽度、透明度或关闭。关闭边框不删除网格数据。
5. 地形使用共享顶点的连续 Mesh。单元格平均高程用于计算共享顶点 Z 值，相邻单元共享同一个顶点，避免形成一块块断开的台阶面。
6. 研究区贴图先裁剪为网格范围，再使用一张纹理和统一 UV 坐标贴到连续 Mesh。不得为每个格网生成独立图片文件。
7. 建筑与地形分开。若输入是含建筑物顶面的 DSM，建筑相交网格暂按“邻近非建筑网格中位数”估计地面高度，然后再从该地面高度拉伸建筑，避免重复叠加楼高。
8. V2 必须导出分层的 Rhino `.3dm`。V3 再增加完整渲染模式、PBR、阴影、天空和更复杂的实时场景。
9. LST、DEM 和气象数据必须保留单位、NoData、比例因子、时间与来源。只有渲染灰度而没有原始数值时，只能标注为“相对指数演示”。
10. 沙盒只执行白名单公式和声明式流程。浏览器版不运行任意 Python、JavaScript、Shell 或 SQL。

## 2. 当前数据首检

### 已可直接用于开发

- 深圳 EPW：`CHN_GD_Shenzhen.594930_TMYx.2004-2018.epw`，站点头记录为 Shenzhen，22.639°N、113.811°E、UTC+8、海拔 4m；包含 8,760 小时典型年数据及 `.stat/.ddy/.wea` 等配套文件。
- 新建筑 Shapefile：3,369 个 Polygon，EPSG:4326，UTF-8。字段包含唯一编号、名称、地址、结构、状况、建筑高度、地上/地下层数、用途和面积。`BLDG_NO` 无重复，建筑高度无空值，范围 3–293m、平均约 21.48m；检测到 6 个无效几何，进入分析前需要修复并保留修复记录。
- 建筑高度字段为 `BLDG_HEIGH`，地上层数字段为 `UP_BLDG_FL`，用途字段为 `BLDG_USAGE`。导入时建立标准字段映射，不改写原字段。

### 已找到的真实数值栅格

- `两个栅格数据/dem`：ArcInfo Binary Grid，869×822、单波段 Float32、约 5m 分辨率。有效像元 529,246，NoData 185,072；数值 0–56.7517，中位数约 12.0733、平均约 13.4082。元数据说明连续型 DEM、垂直单位为米，坐标为 CGCS2000 地理坐标；Rasterio 识别为 EPSG:4019。
- `两个栅格数据/lst`：ArcInfo Binary Grid，146×149、单波段 Float32、30m 分辨率。有效像元 16,570，NoData 5,184；除少量 0 值外，1%–99% 分位约 27.3229–36.4578，最大 38.6238。数据目录自身缺少 `prj.adf`，但根目录 `lst.aux.xml` 明确记录 EPSG:3857，应把该辅助文件作为 CRS 证据保留。
- DEM、LST 与新建筑范围均完整重叠。浏览器不能直接读取 ArcInfo Binary Grid 文件夹，因此开发时需要在本机将它们转换为保留 Float32 数值的 GeoTIFF/COG 派生文件，原文件保持不变。
- LST 数值范围符合摄氏温度量级，但元数据的值单位没有正确填写，也没有采集日期或质量层。确认来源之前可以显示原始数值和色带，但单位标记为“待确认”，不能直接写成 °C。

### 旧的渲染版栅格

- `新的数据/新的数据/深圳DEM.tif` 与 `深圳LST.tif` 是 4 波段 uint8 RGBA 灰度渲染图，只用于底图或对照预览，不进入定量分析。

### 仍缺少的数据

1. LST 的真实单位、来源产品、采集日期时间、比例因子及质量掩膜。当前数值可以分析和展示，但单位必须继续标记为待确认。
2. DEM 是裸地 DTM 还是包含建筑/树木的 DSM，以及垂直基准。元数据已表明长度单位为米，但垂直基准名称仍为 unknown。
3. 可公开的 RGB 正射或卫星影像，用于地形贴图；需保留空间坐标、拍摄日期和公开授权。
4. 研究区边界。现有 V1 边界可以暂用，但必须核对是否与新建筑数据范围一致。
5. 若 DEM 实际为 DSM，需要确认建筑区地面恢复规则。当前暂定为建筑掩膜内使用邻近非建筑网格中位数，最大搜索半径 3 个格网。
6. DEM/LST 中数值 0 的业务含义。当前不能自动把 0 当 NoData；转换时保留 0 并单独统计。
7. Rhino 纹理如果需要在其他电脑打开，需决定交付方式：单独 `.3dm`，或推荐的 `.zip`（`.3dm + texture.png + manifest.json`）。

## 3. V2 首包目标

首包只做可以真实验收的闭环：

1. 读取新建筑、EPW 和两个 ArcInfo Binary Grid，并生成保留 Float32 数值的本地 GeoTIFF/COG 派生文件。
2. 建立统一图层对象和项目数据清单。
3. 新增 Raster → Fishnet、Zonal Mean、Terrain Surface、Texture Drape、EPW Reader、LST Style、Rhino Export 节点定义。
4. 将 DEM/LST 转为网格。网格大小先允许 10m、20m、30m、50m 和自定义值。
5. DEM 按米制高程生成连续曲面，同时在界面提示垂直基准待确认。
6. LST 使用真实 Float32 数值生成色带和网格均值；单位在来源确认前显示为“待确认”，不擅自写成 °C。
7. 显示连续地形 Mesh、可开关网格线、LST 色带、建筑和独立底图。
8. 解析 EPW，显示逐时气温、相对湿度、风速、风向、直射/散射/总水平辐射，支持日期和小时筛选。
9. 导出带图层的 `.3dm`，并同时导出参数清单。
10. 全部分析仍在浏览器 Web Worker 中运行；自然语言不部署到公网。

## 4. 栅格到连续地形的算法

### 4.1 主网格

1. 输入研究区边界、目标格网大小和目标米制 CRS。
2. 自动选择本地米制投影；导出时记录源 CRS、分析 CRS 和本地 Rhino 原点。
3. 研究区范围对齐到格网大小，建立固定行列号和稳定 `cell_id`。
4. 对每个格网统计源像元。只有有效像元数量大于 0 才参与曲面。

### 4.2 网格值

- `mean_value`：有效像元平均值。
- `min_value` / `max_value`：用于质检。
- `valid_count` / `nodata_ratio`：用于可靠性提示。
- `source_unit`：原始单位。当前 DEM 为米；LST 为 `pending_confirmation`。
- `z_value`：用于建模的 Z。当前 DEM 单位为米；垂直夸张仅作为显示参数，不写回原始高程。

### 4.3 建筑区域地面恢复

当 DEM 是 DSM 且包含楼顶高度时：

1. 使用建筑面生成格网掩膜。
2. 建筑相交格网不直接使用其 DSM 平均值作为地面。
3. 搜索 1–3 格范围内的非建筑有效格网，取中位数作为地面 Z。
4. 搜索失败时标记 `ground_fill_status=unresolved`，不静默填 0。
5. 建筑底部使用恢复后的地面 Z；顶部为 `ground_z + building_height`。

这条规则先作为 V2 默认值，后续可替换为 IDW、TIN 或地形形态学滤波节点。

### 4.4 连续 Mesh

1. 每个单元先得到 `cell_mean_z`。
2. 每个共享格网顶点的 Z，取与该顶点相邻的有效单元 `cell_mean_z` 平均值。
3. 相邻单元共用顶点索引，每个格网生成两个三角面。
4. NoData 边界不跨空洞连面。
5. 网格边框另建 Wireframe 图层；隐藏边框不修改 Mesh。

## 5. 贴图与图层结构

底图裁剪到主网格范围后生成一张纹理。每个 Mesh 顶点根据其 XY 在研究区范围内计算 UV。浏览器预览和 Rhino 导出使用同一套 UV，保证位置一致。

建议的 Rhino 图层：

| 图层 | 内容 |
| --- | --- |
| `00_Metadata` | 项目原点、CRS、单位、数据来源与生成时间 |
| `01_Boundary` | 研究区边界 |
| `02_BaseMap` | 底图纹理或底图承载面 |
| `03_TerrainMesh` | 连续地形 Mesh |
| `04_GridWireframe` | 可选网格边框 |
| `05_Buildings` | 建筑体块，底部服从地形 |
| `06_LST` | LST 网格、顶点色或专题面 |
| `07_Analysis` | 后续分析结果 |
| `08_Annotations` | 图例、北向、时间和单位说明 |

浏览器使用 `rhino3dm.js` 创建 `File3dm`、Layer、Mesh、ObjectAttributes 和用户字符串。库按导出功能懒加载，避免增加首次打开首页的负担。贴图交付优先采用 `.zip`，同时保证 `.3dm` 内有顶点色或基础材质作为离线回退。

## 8. 首包验收标准

1. 原始目录的文件大小、修改时间和 SHA256 在处理前后保持一致。
2. 新建筑 3,369 条全部读取；UTF-8 中文字段显示正确；6 个无效几何完成可追溯修复；高度、层数、用途字段含义可见。
3. EPW 恰好解析 8,760 个小时，站点、时区和单位正确。
4. ArcInfo Grid DEM/LST 转换后像元数量、范围、NoData 和统计量与源数据一致；旧 RGBA 版本不进入定量分析。
5. 更改网格大小后，格网数量和运行时间按预期变化；超过上限时给出明确提示。
6. 相邻格网共享顶点，测试曲面没有重复裂缝；NoData 空洞不被错误跨越。
7. 网格边框颜色、宽度、透明度和关闭状态实时生效。
8. LST 相对色带、图例和数值范围一致。
9. `.3dm` 至少包含 8 个约定图层；建筑、地形、LST、底图不混层；模型单位为米。
10. 本机生产构建和既有 V1 测试保持通过。
