## 二、已实现的操作

| 模块 | 实际效果 |
|---|---|
| 首页 | 沙头城市更新可进入；城市交通、校园数字孪生显示后续开发；本地项目保存列表 |
| 本地输入 | Shapefile 完整配套文件或 ZIP、GeoJSON、带坐标的 GeoTIFF、EPW；每组 Shapefile 只形成一个图层 |
| 坐标与网格 | 读取栅格 CRS；快速构建自动选当地 WGS84 UTM；电池中可指定 UTM；禁止把经纬度直接作为米计算 |
| 数值汇总 | 将原像元投影后的四边形与网格求交，按相交面积加权求均值，保留原值、零值、有效数、最值、覆盖率和 NoData 比例 |
| 连续地形 | 共享顶点、三角网；无数据位置保留孔洞；建筑地面估算值与原高程分开 |
| 建筑平整 | 将相连的建筑覆盖格网视为平整区，以外围有依据的非建筑地面估算区域高程；内部继承区域平面；无外围依据的整区保持未解算 |
| 风格 | LST/地形/紫色色带、最小最大值、图层透明度、建筑透明度、边框颜色/像素宽度/透明度/关闭、垂直显示倍率 |
| 贴图 | 复用 V1 灰度卫星底图；独立底图角色；按地形范围重投影采样为一张纹理，共享 UV；支持本地 8-bit RGB GeoTIFF |
| 属性表 | 可向下缩小；按字段选择；分页；显示已选；选择高亮；全图层或选中要素导出 GeoJSON |
| 分析电池 | 字段统计、面积/长度、代表点、缓冲区、点核密度均在 CIRCUIT 内执行；右侧 Analysis 仅保留对话 |
| CIRCUIT 2 | 可拖动浮窗或停靠底部，可调高度；按类别组织电池；端口类型检查、循环检测；多选分组/解组；流程 JSON 导入导出 |
| 沙盒电池 | 受限数学表达式；示例 `clamp((x - 25) / 15, 0, 1)`；不运行任意 Python、JavaScript、Shell 或 SQL |
| 网格裁剪电池 | 按输入面保留相交的网格；不改写源栅格；是整格保留，不声称沿边界精确切碎格网 |
| EPW | 站点、时区、8760 小时典型年、月/日/小时选择；气温、湿度、风速风向、直射/散射/总水平辐射曲线 |
| 本地对话 | 打开属性表、显示/隐藏网格、气象、俯视、全图等预设；未连接模型 API |
| 保存与导出 | 浏览器 IndexedDB 保存 + 可迁移 `.geocim` 包；包保留数据数组、当前分析结果、流程与样式；PNG、GeoJSON、Rhino ZIP |

复杂运算、GeoTIFF 解码、网格、地面估算、公式和 Rhino 编码在浏览器 Worker 中执行。没有新增公共文件上传接口、模型服务或云端用户数据存储。

## 三、第一次录屏建议

1. 打开首页，说明三个示例场景；进入沙头。
2. 用左键平移、滚轮缩放、右键旋转；点击 **Top / 俯视** 或 **Fit scene / 全图**。
3. 在场景面板打开 **Grid borders / 网格边框**，调整颜色和透明度，再关闭；切换 LST 色带。
4. 修改网格大小（例如 30m → 50m），点击 **Rebuild local scene / 重新构建本地场景**。网格越细，运算量越大。
5. 打开 **CIRCUIT 2**，点击运行，查看节点完成状态；切换浮动/停靠，拖动面板上沿改变高度。
6. 在电池窗口点 **JSON ↑**，选择 `examples/V2-LST-formula-circuit.json`，运行受限公式示例。其输出是相对 LST 指标，不是 UTCI/PET。用 `examples/V2-Shatou-circuit.json` 恢复原始 LST 流程。
7. 打开属性表，选择 `mean_value > 35`，导出已选 GeoJSON；拖动表格上沿向下缩小。
8. 点击顶部 **Plugins / 插件** 打开气象插件，切换月、日、小时与辐射曲线。
9. 点击 **Save project / 保存项目**。刷新后从首页本地项目列表重开；也可以在另一台电脑导入 `.geocim` 包。
10. 点击 **Rhino ↓**，解压 ZIP。将 `GeoCIM.3dm`、`texture.png` 和 `georeference.json` 放在同一文件夹，再打开 3DM。

导出 Rhino 使用米和真实高程，界面的垂直夸张倍率不改变导出数据。XY 是相对项目原点的局部坐标，原点与 CRS 同时写入 JSON 和 3DM 文档用户文本。Rhino 若未自动找到纹理，可在材质里选择同目录的 `texture.png`；文件另有顶点色作为离线显示回退。

- 用户说明 DEM 应包含屋顶。V2 因此提供建筑区平整；这是一种估算方法，尚不是经控制点验证的裸地 DTM。网格较粗时，相邻建筑会合成同一平整区，应结合画面检查。

- 浏览器实际下载的 Rhino 包：**8 图层、3,394 对象、1 个纹理材质**；**3,389 个建筑体块全部闭合**；读回检查无效几何数 **0**。

## 五、维护命令

在 `D:\GeoCIM_Demo` 打开终端：

```powershell
# 第一次准备 / 数据变化后重做（原始目录只读）
.\geocim-dev\Scripts\python.exe scripts\prepare_v2_data.py

# 开发：本地预览数据服务保持运行，另开开发页面
pnpm dev
# http://127.0.0.1:5173/v2.html

# 编译、回归、真实数据测试
pnpm build
$env:GEOCIM_REAL_DATA='1'
pnpm test

# 本地预览（占用 8766 时不用重复启动）
.\geocim-dev\Scripts\python.exe scripts\serve_v2.py

# 生成不含私人数据的静态代码预览包
.\geocim-dev\Scripts\python.exe scripts\package_v2_preview.py
```

本地依赖增加 Three.js、rhino3dm，Rhino WASM 按导出操作加载。构建仍有体积提示；它不是运行失败。原 V1 入口 `index.html` 和主代码保持，V2 为独立 `v2.html`。

## 六、发布边界与下一步

`releases/GeoCIM-V2-code-preview.zip` 只含静态代码；新 DEM/LST/建筑/EPW 数据未放入公共目录或 Git。当前生产站仍是 V1。本地数据目录、虚拟环境、导出包、SSH 私钥不纳入源码提交。

后续发布 V2 时，先部署独立预览路径，检查域名与 HTTPS、Worker/WASM 路径、项目导入和资源加载，再切换首页。沙头新示例的公开数据范围需单独确认，或制作经过确认的示例包。回滚可继续指向现有 V1 release。

后续工作：完整气象插件/UTCI 或 PET 所需平均辐射温度和人体参数、批量任务调度、更通用的局部代码运行环境、Food4CIM/CityComfortPlus、PBR 渲染模式。交通和校园场景按用户安排留待后续，本轮未把占位项目当成已完成功能。

技术参考：[Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)、[McNeel rhino3dm](https://github.com/mcneel/rhino3dm)。
