## 本次完成

| 入口 | 行为 |
| --- | --- |
| 固定沙头示例 | 服务器执行地形网格、建筑下方地面估算、LST、Circuit 白名单分析。浏览器负责三维显示、交互和文件导出。 |
| 新建项目 | 默认本地分析，文件读取与计算在浏览器及 Worker 中完成，不上传用户数据。无需登录或 API Key。 |
| 分析图层 | 放工作数据，可调整所属母图层、数据类别、名称、字段设置、属性和 GeoJSON 副本。可作为 Circuit 输入。 |
| 展示图层 | 几何、属性和归类只读。含建筑、边界、底图、地形、交通、专题等子组。显示、颜色、透明度仍可调整；复制到分析图层后再计算。 |
| 结果图层 | 接收转换渔网、场景的地形/LST 数值快照、矢量分析结果和统计报告。矢量结果可查看属性、编辑、继续本地分析及导出。 |
| 右侧 Symbology / 符号系统 | 按属性设置单色、等间隔、分位数、分类色带、透明度和边框。图层归类管理在 Upload。 |

沙头示例同时创建只读展示原件和独立分析副本。工作副本默认隐藏，避免与展示原件重叠；计算不要求输入图层可见。场景数值快照也默认隐藏，作为可检查、可导出的结果保存。没有实测高程的参考平面不会被包装成实测地形结果。

云端仅接受固定示例标识、源图层 ID、流程连接和校验后的参数，不接受用户文件、GeoJSON 坐标或自定义数据。导入用户文件或编辑工作数据会切换为本地分析。固定示例的原始副本仍可切回云端；编辑后的数据或渔网结果需在本地继续分析。云端结果在响应后释放，不写入服务器结果目录。

## 推荐操作顺序

1. 打开 V2.2，选择沙头示例，或选择 **New project** 新建本地项目。
2. 在 **Upload** 设置输入和输出位置，选择母图层及建筑/边界/地形等数据类别，再选择文件。Shapefile 选择同名配套文件或 ZIP；一份数据生成一个子图层。EPW 进入顶部 Weather 插件。
3. 需要保护的数据放到 **Display**。选中后点击 **Copy to Analysis**，得到独立工作副本。修改副本不会覆盖原件或磁盘原始文件。
4. 在 **Scene** 将数值栅格转换为米制渔网。结果自动进入 **Results**。在 **Symbology** 选择属性、色带和边框。
5. 打开 **Circuit**，选输入副本，连接类型相容的端口，设置参数并运行。统计、核密度、缓冲区等分析仍在 Circuit 电池中；对话页保留本地预设控制。
6. 属性表先选字段及要素，再给选中记录设置数值、文本或空值。复杂几何可在 Upload 的 GeoJSON 副本编辑器校验后应用。这不是完整 CAD/GIS 绘制编辑器；栅格通过角色、单位、重采样及安全公式处理，没有逐像元画笔。
7. 导出 GeoJSON、统计 JSON、PNG 或 Rhino ZIP；点击 **Save project** 同时保存浏览器项目记录并导出 `.geocim` 项目包。

## 本地输入、输出位置

- 默认输入：用户通过文件选择框指定的本地文件；默认输出：浏览器下载目录。
- 支持文件系统授权的浏览器提供 **Choose input folder / Choose output folder**。输入目录只请求读取权限，输出目录请求写入权限，两者不能是同一目录。
- 目录权限必须通过浏览器自己的文件夹选择对话框授予；网页不能自动获得任意 `C:\` 或 `D:\` 路径权限。页面只展示授权文件夹名，不伪造完整系统路径。
- 输出文件带时间戳及随机标识，创建新文件，不覆盖原始文件。目录递归导入会拒绝重名文件，避免混合同名 Shapefile 配套文件。
- 重新打开项目后需重新授权文件夹。浏览器不支持目录授权时，继续使用选文件与下载即可。Chrome/Edge 的相关机制见 [官方 File System Access 文档](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。
- 本版“本地”指浏览器本地计算，不是桌面 Python 服务。浏览器关闭会结束未保存任务；应主动保存 `.geocim` 包。清理浏览器数据会移除该浏览器内的项目记录，已导出的文件不受影响。

## 文件与运行位置

- 项目源码：`D:\GeoCIM_Demo`；分支 `codex/v2`。
- V2 网页：`src/v2/`；云计算服务：`server/`。
- 本地示例衍生文件：`data/v2/shatou/`，目录不提交 GitHub。
- 原始 GIS 目录保持只读；未将原始数据目录、密钥或备份部署到公开网站目录。
- 本地构建：在项目目录运行 `pnpm build`。
- 本地预览：`geocim-dev\Scripts\python.exe scripts\serve_v2.py`，访问 <http://127.0.0.1:8766/v2.html>。
- 完整回归：PowerShell 设置 `$env:GEOCIM_REAL_DATA='1'` 后运行 `pnpm test`。
- 云计算构建与本地联调：`node scripts/build_cloud.mjs`，然后 `node scripts/test_cloud.mjs`。
- 打包：`geocim-dev\Scripts\python.exe scripts\package_v22.py`，结果位于 `releases/`，发布信息为 `releases/v22-release.json`。

## 服务器部署与回滚

服务器保留静态 Nginx 网站，只新增一个监听回环地址的固定示例服务。Node.js 24.21.0 安装在项目专用 `/opt/geocim-v2/runtime/`，下载来自 Node.js 官方站并通过官方 SHA-256 校验，未替换系统 Python。服务名 `geocim-v2`，云端代码和固定数据位于 `/opt/geocim-v2/current`，网页位于 `/www/wwwroot/geocimplus/current`。

服务限制：单任务并发、每 IP 每分钟 8 次请求、64 KiB 请求体、45 秒任务时限、384 MiB 服务内存上限、80% 单核 CPU 配额。使用只读文件系统保护、临时动态用户，无公开上传接口，也没有模型任意代码执行入口。云示例采用至少 30 m 网格；需要更细网格时选择本地分析。

部署脚本 `scripts/deploy_v22.sh` 会备份 Nginx、旧站点和旧服务指针，然后验证配置、切换版本。`scripts/rollback_v22.sh` 接受部署编号作为参数，恢复该次部署之前的站点与服务；首个 V2.2 版本的回滚会停用新增云服务。备份存放在 `/var/backups/geocim/<部署编号>/`。脚本已做语法检查；没有为了测试而回滚正在使用的线上网站。

打包脚本将 V2 HTML 同时写入公开 `index.html` 与 `v2.html`，将本地构建的 V1 HTML 写为 `v1.html`。主入口和 HTML 使用重新验证缓存策略，带哈希的静态资源继续缓存；以后发布不会恢复成 V1 首页。源代码开发入口保持兼容，本地 V2 使用 `/v2.html`。

部署历史及当前编号见本机 `releases/v22-release.json`。需要回到 V2.2 之前的纯 V1 状态时，可用首个 V2.2 部署编号 `20260921-051839-v22` 运行回滚脚本。不要手工覆盖 `current` 指向的文件，继续使用版本目录发布。

## 验证与当前边界

- 49 项自动测试通过，含真实 DEM/LST/建筑数据、Shapefile、坐标、NoData、图层权限、独立复制、目录输入输出规则、Circuit 和 Rhino 分层回读。
- 正式 HTTPS 接口实测：13,814 个有效地形格；50 m 双线性 LST 为 4,953 个有效渔网面；3,369 条建筑高度均值 21.47735233 m。含上传字段的云请求返回 422。
- 浏览器已验证新建本地项目、展示只读导入、复制、换母图层、属性修改且原件不变、云端示例、LST 渔网、统计报告、保存项目。文件夹授权逻辑用测试替身验证；本轮未替用户确认系统文件夹权限，需用户首次使用时自行选择。
- 线上 API 实测与本地联调记录保存在 `reports/v2.2/`。该目录不进 GitHub。
- DSM 建筑下方地面是邻近像元估算，不是实测裸地；LST 为用户确认的摄氏度、2026 年 8 月，具体拍摄日时及产品质量层未知。插值不会增加真实空间细节。EPW 是站点典型气象年，不能当作现场热舒适实测值。
- 目前未接入在线 AI API、交通和校园实时系统。沙盒为有参数校验的安全公式与白名单电池，不是任意 Python、Shell 或 SQL 执行环境。
